Lab: Using Amazon Inspector for Vulnerability Assessment and Remediation
Overview
This lab focused on using Amazon Inspector to identify, analyze, and remediate security vulnerabilities in AWS resources, with a specific emphasis on AWS Lambda functions. The scenario simulated a real-world development environment where a company required an automated security service to continuously assess deployed workloads for known vulnerabilities in both software packages and application code.
The goal was to understand how Amazon Inspector integrates with AWS services, how vulnerability findings are presented, and how remediation actions can improve the security posture of serverless applications.

Explanation (What I did and why)
I began by activating Amazon Inspector in the AWS account so that continuous vulnerability scanning could be performed. This activation enabled Inspector to automatically assess supported resources, including AWS Lambda functions, without requiring agents or manual configuration. This step was essential to ensure that all newly deployed or updated resources would be scanned as part of an ongoing security process rather than a one-time check.
Once Inspector was active, I reviewed the environment coverage dashboard to confirm that all Lambda functions were being scanned. This validation ensured that the service was correctly monitoring the intended resources.
ADD IMAGE
Next, I analyzed the vulnerability findings generated by Amazon Inspector. The findings identified multiple vulnerabilities associated with a Lambda function, including a medium-severity issue related to an outdated third-party Python package (requests). I examined the detailed vulnerability report, which included severity level, impacted resource, and the associated CVE identifier. To deepen my understanding, I referenced the external National Vulnerability Database (NVD) link provided in the report, which explained the nature and potential impact of the vulnerability.
After reviewing the findings, I focused on remediation. The Inspector report recommended upgrading the vulnerable package to a secure version. I updated the Lambda function’s dependency configuration by modifying the requirements.txt file to allow the latest version of the package to be installed. This approach ensured that the function would use a patched and actively maintained version of the dependency, reducing the attack surface.
Once the updated code was deployed, I revisited Amazon Inspector to confirm that a new scan had been triggered automatically. Reviewing the findings again allowed me to verify that the vulnerability status had changed from Active to Closed, confirming that the remediation had been successful.

Output Explanation (What the result shows)
The final output demonstrated that Amazon Inspector successfully identified a vulnerability, provided actionable remediation guidance, and automatically re-evaluated the resource after the fix was applied. The closed vulnerability finding confirmed that updating the Lambda dependency resolved the issue.
This result showed how Amazon Inspector supports continuous security monitoring, helps enforce secure development practices, and enables teams to quickly detect and address vulnerabilities in serverless applications without disrupting development workflows.
